## 一、产品背景

随着健身人群增长，越来越多用户需要：

- **科学训练记录**
- **训练计划管理**
- **饮食记录与热量计算**
- **数据分析**
- **AI 训练与饮食建议**

现有市场产品（如 MyFitnessPal、Strong、Hevy）在使用中存在：

- 训练与饮食数据分离
- 缺少智能分析与个性化建议
- 训练流程不够灵活，效率较低

**本产品目标：打造一个 AI 辅助的「训练 + 饮食一体化」健身管理 App。**

---

## 二、产品目标

**核心能力：**

1. 训练计划管理
2. 动作库与训练记录
3. 组数与计时管理
4. 饮食记录与热量计算
5. 数据统计分析
6. AI 训练与饮食建议（V2+）

**核心价值：**

帮助用户：

- 减脂
- 增肌
- 提升力量
- 长期保持健身习惯，形成正向反馈闭环

## 三、用户画像

### 3.1 健身新手

- **特点**
  - 对训练动作与计划缺乏认知
  - 不会计算每日所需热量与营养结构
- **需求**
  - 自动生成训练计划或简单模板
  - 动作讲解与注意事项
  - 基于目标的饮食建议与热量范围

### 3.2 健身爱好者

- **特点**
  - 有一定训练经验
  - 希望系统化记录训练，关注训练数据
- **需求**
  - 详细训练记录（重量、次数、组数、休息时间）
  - PR（个人最佳）记录
  - 训练量、频率等数据统计与趋势分析

### 3.3 减脂用户

- **特点**
  - 对身材和体重较敏感，关注体重变化
- **需求**
  - 热量缺口管理
  - 便捷饮食记录
  - 体重和体脂变化趋势

## 五、用户体系与权限

## 七、训练计划

### 7.1 功能说明

用户可以创建多个训练计划。每个计划包括：

- 计划名称
- 每周训练天数
- 每日训练部位及动作列表

示例：

- 计划名称：Push Pull Legs
  - Day1：胸 + 三头
  - Day2：背 + 二头
  - Day3：腿

### 7.2 计划约束与状态

- **多计划管理**
  - 单个用户允许存在多个计划。
  - 最新创建且处于进行中状态的计划为「当前计划」。
  - 其余计划为「历史计划」，可查看和复制，不可继续执行。
- **计划生效逻辑**
  - 计划默认自创建当天开始生效。
  - 不支持「跳日训练」，当天仅可执行当日对应训练日。
- **计划修改**
  - 进行中的计划允许修改训练天数、动作及组数等配置。
  - 修改后：
    - 历史训练记录不变。
    - 展示计划结构时按「最新配置」展示。

## 八、动作库

### 8.1 动作基础信息

系统提供内置动作库，每个动作包含：

- 动作名称
- 主要训练部位（胸、背、腿、肩、二头、三头、核心等）
- 动作图片或插画
- 动作讲解（文字）
- 注意事项
- 可选元信息：器械类型（杠铃/哑铃/器械/自重）、难度等级

示例动作：

- 卧推
- 深蹲
- 硬拉
- 引体向上
- 杠铃划船

### 8.2 自定义动作

- 用户可以新增自定义动作，需填写：
  - 动作名称
  - 选择训练部位
  - 可选上传图片
  - 简单动作说明（可选）
- 自定义动作存入用户个人动作库，对本人可见。

## 九、新建训练流程概述

1. 用户在「训练」Tab 点击「开始训练」或首页快捷入口。
2. 选择训练模式：
   - 基于当前计划训练
   - 自由训练（不依赖计划，自选动作）
3. 进入「动作选择页面」，按肌群/搜索等方式选择动作。
4. 为每个动作配置组数、重量、次数、休息时间等参数。
5. 进入「训练执行页面」，开始正式训练。
6. 训练过程中可追加动作和组数，可修改组参数。
7. 训练结束后生成训练报告，并更新统计数据及 PR 记录。

## 十一、动作配置

### 11.1 配置内容

用户可以为每个动作配置训练参数：

- 组数
- 每组重量（kg）
- 每组次数（次）或时间（秒）
- 组间休息时间（秒）
- 是否开启每组计时

示例：

- 1 组：50kg × 8次
- 2 组：50kg × 10次
- 3 组：50kg × 12次

### 11.2 支持操作

- 修改组数（增减组）
- 修改单组重量、次数、时间
- 修改默认组间休息时间
- 是否开启计时训练（针对平板支撑等动作）

## 十二、训练执行页面

### 12.1 顶部区域

- **计时器**
  - 显示本次训练总时长
  - 支持开始/暂停
- **训练标题**
  - 显示当前训练名称（默认使用计划名称 + Day 名称，可编辑）
- **AI 按钮（预留）**
  - 进入「AI 建议」页面（V2 实现，V1 可显示“敬请期待”）
- **完成按钮**
  - 结束训练，生成训练报告
  - 若有未完成动作/组，弹窗确认：保存为「未完成训练」还是继续

### 12.2 动作卡片区域

- 显示当前执行的动作：
  - 动作图片、名称
  - 「设置」按钮：修改当前动作配置、删除动作等
- **组列表**
  - 每组显示：
    - 序号（1/2/3/…）
    - 重量（kg）
    - 次数（次）或时间（秒）
    - 完成勾选按钮
    - 更多菜单（…）：编辑、删除、复制上一组
  - 支持「每组计时」：完成某组后自动启动计时，配合休息倒计时使用
- **追加组**
  - 「新增一组」按钮：在尾部追加一组，默认复制上一组配置
- **动作历史**
  - 「动作历史」按钮：弹出历史记录，展示该动作最近 N 次训练结果，用于参考负重与次数调整
- **难度反馈**
  - 简单 / 正常 / 困难 三档，用户勾选主观难度，用于数据分析和 AI 建议

### 12.3 底部工具栏

- 最小化：将训练界面缩为悬浮条，计时继续
- 更多：进入训练相关设置，如结束训练、重置训练、统一调整休息时间等
- 加动作：训练中途跳转到「动作选择页面」继续添加动作
- 写心得：为本次训练添加整体备注（例如“今天状态一般”“右肩不适”）
- 其他按钮名称可根据最终交互调整

## 十三、训练计时系统与组间休息

### 13.1 训练模式

- **次数训练模式**
  - 每组记录：重量 + 次数
  - 示例：50kg × 10
- **计时训练模式**
  - 每组记录：动作时间（如 30 秒）
  - 示例：平板支撑 30 秒

### 13.2 组间休息

- 每组完成后自动进入休息状态：
  - 默认休息时间（如 90 秒，可配置）
  - 显示剩余休息时间
  - 提供「跳过休息」按钮
- 用户可在训练设置中修改默认休息时间，也可单独为某一动作设置不同休息时长。

### 13.3 提前结束单组

- 用户可以提前结束某一组：
  - 行为：点击完成 → 记录当前已完成数值 → 进入休息状态。
  - 若次数未达到预设，允许用户直接编辑为实际次数（例如计划 10 次，实际做 7 次，记录为 7）。

## 十四、训练记录与状态

### 14.1 训练中途退出

- 若用户在训练过程中直接退出：
  - 系统将当前训练会话标记为「未完成训练」并保存已有数据。
  - 在统计和列表中做特殊标记，以便区分。

### 14.2 训练历史与动作历史

- 用户可在「训练记录」中查看每次训练详情，包括：
  - 训练日期、训练时长
  - 动作列表及每组记录
  - 本次总训练量、消耗热量（估算）
- 某一动作的历史记录，可展示最近 N 次（例如 5 次）的该动作表现，支持在训练执行过程中快速查看。

## 十五、训练统计与 PR 记录

### 15.1 训练结束报告

训练结束后生成报告，内容包括：

- 训练时长
- 训练动作数
- 总训练量（如 kg 总和）
- 估算消耗热量
- 主观难度反馈（如有）
- 简要总结（后续可由 AI 生成）

示例：

- 训练时长：75 分钟
- 总训练量：8500 kg

### 15.2 PR（Personal Record）记录

系统记录用户的个人最佳成绩，包括：

- 单次最大重量（1RM 或训练中最大重量）
- 某重量下的最大次数
- 最佳训练量

示例：

- 卧推最大重量：100kg

## 十六、饮食模块

### 16.1 饮食记录

用户可以按餐次记录每日饮食：

- 早餐
- 午餐
- 晚餐
- 加餐

每一条饮食记录包括：

- 食物名称
- 重量（g / ml）
- 自动计算热量与营养素（来自食物数据库或自定义食物）

示例：

- 鸡胸肉 150g

### 16.2 单位与精度

- 所有食物统一使用 g / ml 作为单位。
- 首版不提供「个 / 杯 / 勺」等换算单位（可在后续版本扩展）。

### 16.3 食物数据库

- 食物基础信息（每 100g）：
  - 热量（kcal）
  - 蛋白质（g）
  - 碳水化合物（g）
  - 脂肪（g）

### 16.4 自定义食物

- 用户可新建「自定义食物」：
  - 必填：名称、热量、蛋白质、碳水、脂肪（以每 100g 为单位）
  - 自定义食物仅对本人可见，并可在后续记录中复用。

### 16.5 录入效率优化

- 支持快速复制：
  - 一键复制上一餐至当前餐次。
  - 一键复制前一天同一餐次的饮食到今天。

## 十七、热量统计与每日能量平衡

系统根据训练与饮食记录，计算：

- 当日摄入热量
- 当日消耗热量（基于基础代谢 + 活动/训练估算）
- 当日热量差（摄入 - 消耗）

示例：

- 摄入：2200 kcal
- 消耗：2500 kcal
- 热量差：-300 kcal（热量缺口）

## 十八、数据统计模块

### 18.1 数据展示内容

- 体重变化曲线
- 训练频率（周/月维度）
- 训练总量变化
- 热量趋势（摄入/消耗/差值）

### 18.2 时间范围与粒度

- **默认视图**
  - 本周（周一至当前日）
  - 本月（1 日至当前日）
- **粒度切换**
  - 按日：展示最近 7–30 天数据
  - 按周：展示最近 8–12 周数据
  - 按月：展示最近 6–12 个月数据

### 18.3 体重记录频率与展示

- 用户每天可多次记录体重。
- 展示规则：
  - 日视图：同一日多次记录取平均值作为该日体重。
  - 周/月视图：基于日均体重再聚合为周/月数据。

## 十九、通知与提醒

- **训练提醒**
  - 用户可在设置中开启训练提醒。
  - 根据训练计划的训练日及用户设置的时间，发送本地通知或推送提醒进行训练。
- **饮食提醒**
  - 用户可选择开启三餐提醒，按早餐/午餐/晚餐预设时间提醒记录饮食（加餐提醒可选）。
- 通知中不展示体重/体脂等敏感具体数值，仅展示泛化文案（如「今天的训练还没完成」）。

## 二十、AI 功能（规划，V2+）

### 20.1 总体说明

- AI 服务通过 OpenAI 提供。
- V1 预留入口与数据结构，V2+ 实现具体能力。
- 当前以「文字建议」为主，不自动修改用户计划或记录。

### 20.2 AI 训练建议

- **调用入口**
  - 「AI 建议」独立页面中的训练建议区域，由用户手动触发。
- **输入数据**
  - 用户基础信息与目标。
  - 最近 N 次训练记录（如 10 次）：训练频率、动作（部位）、重量、次数、训练量、主观难度等。
- **输出格式**
  - 至少 3 条结构化建议，每条包括：
    - 建议文案（例如「胸部训练偏少，建议每周增加 1 次」）
    - 建议重点部位（胸 / 背 / 腿 / 全身等）
    - 建议执行频率（如「下周每周 2 次背部训练」）
- **行为约束**
  - 仅展示建议，不直接修改训练计划。

### 20.3 AI 饮食建议

- **调用入口**
  - 「AI 建议」页面中的饮食建议区域，由用户手动触发。
- **输入数据**
  - 最近 7 天饮食记录（每日总热量及三大营养素结构）。
  - 最近 7 天体重变化。
  - 用户当前目标（减脂/增肌/力量/保持）。
- **输出格式**
  - 推荐每日：
    - 总热量范围
    - 蛋白质/碳水/脂肪摄入范围（g 或 kcal）
  - 若干条可执行建议和示例食物组合（如「晚餐增加 100g 鸡胸肉」「减少含糖饮料」）。
- **行为约束**
  - 仅提供文字建议，不自动改动用户饮食记录。

## 二十一、异常状态与边界情况

- **网络状态**
  - V1 不支持离线记录，训练和饮食记录操作均需在线。
  - 无网络时禁止开始新训练和新增饮食记录，并提示「当前无网络，无法同步数据」。
- **空数据状态**
  - 统计页无数据时：
    - 显示友好文案 + 引导按钮，如「还没有训练记录，去完成今天的第一节训练吧」。
  - 饮食记录、训练记录列表为空时，展示说明文案并给出记录入口。
- **删除与撤销**
  - 训练会话：支持删除整次训练，删除后不可恢复。
  - 训练细节：支持删除单个动作或单组记录。
  - 饮食记录：支持删除单条食物记录，并实时更新当日统计。
  - 可选：提供短时间（如 5 秒）内的「撤销」入口，视开发成本决定。

## 二十四、技术与非功能需求（NFR）

### 24.1 性能与体验

- App 冷启动时间 < 3 秒（主流中高端机型）。
- 关键操作（训练中切换动作、勾选完成一组、录入饮食条目）本地反馈时间在 100–200ms 内。
- 对网络延迟采用乐观更新策略：先更新本地 UI，再后台同步，失败时提示并回滚。

### 24.2 数据安全与隐私

- 所有网络请求使用 HTTPS。
- 密码等敏感信息加密存储，不允许明文存储。
- 提供账号注销能力（可在后续版本实现），注销后删除或匿名化用户数据。
- 敏感数据（体重、体脂等）在通知中不展示具体数值。

### 24.3 日志与埋点

- 必须埋点事件：
  - 训练计划：创建 / 开始执行 / 完成
  - 训练会话：中途退出 / 正常完成
  - 饮食记录：创建 / 删除
  - 体重记录：新增/修改
- 埋点数据用于产品分析与后续 AI 建模（需在隐私协议中说明）。

### 24.4 多语言与地域

- V1 仅支持简体中文。
- 单位体系：
  - 体重：kg
  - 热量：kcal
- 后续国际化时再加入 lbs 等单位及切换逻辑。

## 二十九、名词定义（建议）

- **训练计划（Workout Plan）**：由多个训练日组成的长期结构化训练方案。
- **训练日（Plan Day）**：计划中的某一天配置，包含若干训练动作。
- **训练会话（Workout Session）**：用户实际完成的一次训练过程，对应某一天的训练记录。
- **动作（Exercise）**：具体的训练动作，如卧推、深蹲等。
- **组（Set）**：动作中的一个执行单元，记录重量、次数或时间。
- **餐次（Meal）**：当天的一次进食记录，如早餐、午餐、晚餐、加餐。

🔥 deploy.sh（完整版）
#!/bin/bash

set -e

echo "🚀 开始部署 Fitness App（规范版）..."

# =====================
# 统一目录结构
# =====================

APP_DIR="/app"
TOOLS_DIR="/opt/tools"
DATA_DIR="/data"
LOG_DIR="/var/log/fitness"

mkdir -p $APP_DIR
mkdir -p $TOOLS_DIR
mkdir -p $DATA_DIR/mysql
mkdir -p $DATA_DIR/redis
mkdir -p $LOG_DIR

echo "📁 目录结构创建完成"

# =====================
# 安装基础依赖
# =====================

apt update -y
apt install -y wget tar nginx

echo "📦 基础依赖安装完成"

# =====================
# 安装 Java（统一路径）
# =====================

cd $TOOLS_DIR

if [ ! -d "java" ]; then
    echo "⬇️ 安装 Java..."
    wget https://download.oracle.com/java/17/latest/jdk-17_linux-x64_bin.tar.gz -O java.tar.gz
    mkdir java
    tar -xzf java.tar.gz -C java --strip-components=1
fi

export JAVA_HOME=$TOOLS_DIR/java
export PATH=$JAVA_HOME/bin:$PATH

echo "☕ Java 安装完成"

# =====================
# 安装 MySQL（使用系统包）
# =====================

apt install -y mysql-server

systemctl start mysql
systemctl enable mysql

echo "🗄️ MySQL 安装完成"

# =====================
# 初始化数据库
# =====================

mysql -u root <<EOF
CREATE DATABASE IF NOT EXISTS fitness_app;
EOF

echo "📊 数据库初始化完成"

# =====================
# 安装 Redis
# =====================

apt install -y redis-server

systemctl start redis-server
systemctl enable redis-server

echo "⚡ Redis 安装完成"

# =====================
# 配置 Nginx
# =====================

cat > /etc/nginx/sites-available/fitness <<EOF
server {
    listen 80;

    server_name _;

    location / {
        proxy_pass http://localhost:8080;
        proxy_set_header Host \$host;
        proxy_set_header X-Real-IP \$remote_addr;
    }
}
EOF

ln -sf /etc/nginx/sites-available/fitness /etc/nginx/sites-enabled/

systemctl restart nginx

echo "🌐 Nginx 配置完成"

# =====================
# 创建应用启动脚本
# =====================

cat > $APP_DIR/start.sh <<EOF
#!/bin/bash

export JAVA_HOME=$TOOLS_DIR/java
export PATH=\$JAVA_HOME/bin:\$PATH

cd $APP_DIR

echo "🚀 启动后端服务..."

nohup java -jar app.jar > $LOG_DIR/app.log 2>&1 &
EOF

chmod +x $APP_DIR/start.sh

# =====================
# 创建停止脚本
# =====================

cat > $APP_DIR/stop.sh <<EOF
#!/bin/bash

PID=\$(ps -ef | grep app.jar | grep -v grep | awk '{print \$2}')

if [ -n "\$PID" ]; then
    kill -9 \$PID
    echo "🛑 应用已停止"
else
    echo "⚠️ 未找到运行中的应用"
fi
EOF

chmod +x $APP_DIR/stop.sh

# =====================
# 创建重启脚本
# =====================

cat > $APP_DIR/restart.sh <<EOF
#!/bin/bash

$APP_DIR/stop.sh
sleep 2
$APP_DIR/start.sh
EOF

chmod +x $APP_DIR/restart.sh

# =====================
# 输出提示
# =====================

echo ""
echo "🎉 部署完成！"
echo ""
echo "👉 上传你的后端："
echo "scp target/app.jar root@服务器:$APP_DIR/"
echo ""
echo "👉 启动服务："
echo "cd $APP_DIR && ./start.sh"
echo ""
echo "👉 查看日志："
echo "tail -f $LOG_DIR/app.log"
echo ""
echo "👉 访问："
echo "http://服务器IP"
echo ""
